## Audit boundary and follow-ups

- This is a source-level inventory. A full parity claim requires feature-by-feature test evidence and Android physical-device tunnel verification; iOS is a new platform implementation, not reference parity.
- The reference includes experimental/recent formats and custom-core capabilities. An enum or parser is not proof that a core build supports every option.
- The checked out `CLAUDE.md` and `GEMINI.md` are tiny routing stubs. Root `AGENTS.md` and scoped service/UI `AGENTS.md` were reviewed; no reference code has been copied.
- Next audit steps: inspect all Xray-core and Go module transitive license notices; enumerate all `fmt` behavior and all settings/ruleset serialization; execute reference-specific tests/build where Android SDK/JDK/Go/NDK become available; test Android and iOS tunnel behavior on real devices.
